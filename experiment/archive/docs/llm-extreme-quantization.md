# LLM 极致量化：NPU 亲和的渐进式混合精度量化通用方案（NQ-PG）

> 主题：**LLM 极致量化**（Extreme Quantization）
> 性质：与具体模型无关的**通用方案**，适用于任意 LLM / VLM / MoE 在昇腾 NPU 上的无损极限压缩
> 方法定位：不止于复现 SLQ，而是提出一套 **NPU-Affinity Progressive Group Quantization（NQ-PG）** 新框架

---

## 【摘要】

**一句话概括**：提出 NQ-PG——面向昇腾 NPU 的"硬件对齐量化原语 + 组级 Shapley 敏感度 + 预算驱动 ILP + 经验闭环定界 + 硬件亲和打包部署"五段式通用量化框架，解决大模型在国产算力上"显存贵、低位宽崩坏、论文方法无法落地"三大痛点，目标是在 **3.4–3.8 bpp**（远低于主流 INT4 的 4.16 bpp）下实现 **下游任务平均零损失** 与 **存储/显存 3.2× 压缩**。

---

## 【创新方案描述】

### 1. 创意概述（Idea）

把"极限量化"从算法命题改造成**硬件协同命题**：

- 学术界最新方法（如 SLQ）只证明"可以压到 3.x bpp"，但**没有国产算力适配**；
- 现有 NPU 量化工具（如 AMCT GPTQ）只有 **int4 / int8 两档**，无混合精度与敏感度分配；
- 生产侧需要的是"**压到极限且无损，并且能直接上 vLLM**"。

NQ-PG 不发明新的敏感度理论，而是把敏感度理论**NPU 化、工程化、闭环化**：

```
硬件对齐原语 → 单 Hessian 多档 GPTQ → 组级 Shapley 并行采样
      → 预算 ILP + 实测闭环 → 硬件亲和打包与 TP 部署
```

### 2. 方案组成（五段式）

#### ① 硬件对齐的量化原语
- **非对称 INT，group size = 128**（对齐 Ascend GEMM tile，避免跨 tile 量化碎片）；
- scale bf16 + zero int4 计费（+0.156 bpp），与 INT4/INT2 NPU GEMM 接口对齐；
- **embedding / lm_head / norm 保留 BF16**（约占 11% 参数，换取稳定性与工程量可控）。

#### ② 一次 Hessian、多档位 GPTQ
- 每个 Linear 只采集一次输入 Hessian，**顺产出 {2,4,6,8} 全档位**，避免逐档重复校准；
- 二阶误差补偿（OBQ）抵消低位宽误差；
- **NPU 兼容**：`torch.linalg` 在 NPU 不支持，大矩阵求逆自动落 CPU 回迁；
- **断点续跑**：每块落盘，OOM/中断后直接从已存块继续（27B 实测从 3 次 OOM 变成一次通过）。

#### ③ 组级 Shapley 敏感度（并行化 + 成本可控）
- **分组粒度对齐 vLLM 融合 kernel**：`q/k/v` 合为一组、`gate/up` 合为一组、小门控投影单独成组；
- 多 bitwidth Shapley（Alg.1）用 **top-10 KL** 度量；
- **多卡多进程并行 + 按 seed 平均**（等效排列数翻倍），把单卡数十小时降到一张卡一晚；
- 负边际自动钳制 ≥0 并强制位宽单调（抗小样本噪声）。

#### ④ 预算驱动 ILP + 经验闭环（替代 TL 外推）
- 敏感度库生成后，**用 HiGHS MILP 在每个平均位宽预算下最小化预测 KL**，一次跑出一组候选（如 3.4 / 3.6 / 3.8 / 4.0）；
- **跳过 SLQ-TL 的"退化锚点线性外推"**：大模型 4-bit 常已无损，2-bit 锚点会把预算推到 4.5 bpp 以上；
- 改为**真实评测定界**：对候选配置逐个跑 zero-shot，找无损下界——这是本方案相对 SLQ 的**方法论级修正**。

#### ⑤ 硬件亲和打包与部署
- 权重按 tile 边界位打包，融合投影共享位宽，TP 分片边界不跨 group；
- checkpoint 产出为 **fake-quant（BF16 落在整数格点）**，可无缝进 vLLM-Ascend；
- 部署采用 **spawn 多进程模式 + OMP_NUM_THREADS=1**（规避 fork 线程池断言），并补齐 VLM 预处理文件；
- 小投影保护规则：**参数量 < 阈值（如 20M）的投影默认最低 4-bit**（实验发现 `in_proj_a/b` 此类小门控最敏感，几乎零成本却防崩）。

### 3. 创新点：与现有方案的差异

| 对比对象 | 差异 |
|----------|------|
| **SLQ（官方）** | 不是移植而是升级：① NPU 全栈适配；② 把 TL 线性外推改为**预算扫描 + 实测闭环**；③ 分组粒度对齐 vLLM 融合 kernel |
| **AMCT GPTQ（NPU 现有）** | 从 int4/int8 两档扩展为 {2,4,6,8} 多档 + Shapley 分配；单 Hessian 全档；可断点续跑 |
| **统一 INT4** | 无损前提下位宽再降 ~13%（3.600 vs 4.156）；把预算集中到 0.03% 的敏感小投影 |
| **SmoothQuant/平滑类** | 不需要额外激活平滑，二阶补偿 + 混合精度即可稳定 |

### 4. 解决问题（客户痛点）

1. **显存贵**：大模型 BF16 放不下单卡，量化后权重显存理论降至 1/3；
2. **低位宽崩坏**：小模型 4-bit 损失明显，大模型靠混合精度可无损到 3.6 bpp；
3. **国产算力缺方法**：没有 NPU 可用的敏感度混合精度框架；
4. **部署不可控**：量化产物与 vLLM 加载链断裂。

### 5. 三维度说明

| 维度 | 说明 |
|------|------|
| **创新性** | 首个在 NPU 上把 Shapley 敏感度 + 混合精度做成**通用、可复现、可生产**的框架；提出"实测闭环定界"替代论文 TL 外推 |
| **商业价值 / 效率提升** | 存储与显存理论 **3.17× 压缩**；部署显存门槛从 2×32 GB 降到 2×16 GB；推理卡成本与功耗随显存线性下降 |
| **可行性** | 已在真实集群以 27B 为验证实例全流程实测（496 层 × 4 档、400 组 Shapley、500 样本评测、TP=2 部署 PASS），流水线 12–13 h 可复现 |

## 【创意价值呈现】

### 1. 目标用户

| 用户 | 使用方式 |
|------|----------|
| **大模型推理平台团队** | 直接采用 NQ-PG 产出 checkpoint 上 vLLM-Ascend，降低显存门槛 |
| **模型部署工程师** | 复用 NPU 适配层、敏感度库、ILP 分配、部署脚本，迁移到任意 LLM/VLM/MoE |
| **模型压缩研究团队** | 基于组级 Shapley 库做 3-bit 极限、门控保护、小模型稳健性研究 |
| **企业私有化部署客户** | 不采购 80 GB 级 HBM，用现有 32 GB 卡跑 27B+ 级模型 |

### 2. 量化收益（以 27B 验证实例为依据）

| 指标 | BF16 基线 | NQ-PG（实例） | 提升 |
|------|-----------|---------------|------|
| 平均位宽 | 16 bpp | **3.600 bpp** | **4.44× 压缩** |
| 模型存储（INT 打包） | 54.71 GB | **17.26 GB** | **3.17×** |
| 每卡权重（TP=2） | 25.61 GiB（fake） | ≈ **8.1 GiB**（INT） | **≈3.2×** |
| 下游精度（6 任务 × 500） | 0.6237 | **0.6237（100.0%）** | **零损失** |
| 部署验证 | — | **TP=2 PASS，KV 23.99 GiB / 326K tokens** | 可生产 |

> 注：以上为 27B 实例实测；对更大模型（70B+）或更低位宽，预期收益随参数量线性放大，但需按同样的"预算扫描 + 实测闭环"重新定界。

### 3. 对比基准

| 方案 | bpp | 精度 | 说明 |

## 落地路径建议

1. **工程化**：把 fake-quant 接成真 INT 打包加载（Humming 或自研 kernel），把 3.17× 显存收益从理论变实测。
2. **模板化**：将 NPU 适配层、敏感度库、ILP 分配、部署脚本封装成可配置工具链，适配任意 LLM/VLM/MoE。
3. **产品化**：对内形成"32 GB 卡可跑 27B+ 模型"的能力卖点；对外可作为昇腾推理平台量化参考实现。
4. **规模化**：提高 Shapley 采样（8k → 32k tokens），预期把无损下界进一步下探到 3.4–3.5 bpp。

---

*本方案为通用框架提案；所有实例数字来自真实实验日志，仅作可行性佐证，不构成对任意模型的精度承诺。*
