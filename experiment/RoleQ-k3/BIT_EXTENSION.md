# RoleQ 的 bit 扩展可行性分析

- 目标：把量化精度损失压到 **<0.5%**
- 问题：RoleQ 能否从 ternary（1.59 bpw）扩展到任意 bit（如 3-bit），并用更高 bit 换取更小损失
- 依据：论文 arXiv:2610.21808 的 Table 2/3/4 与 Appendix A/D
- 结论日期：2026-10-19

---

## 0. 结论

1. **格式上可以扩展**：RoleQ 规定的是 scale 的轴（reader 行 / writer 列），与码本宽度正交。论文明确说明规则 “holds on integer and ternary grids”，并给出了 INT3/INT4 结果。
2. **3-bit 本身达不到 0.5%**：论文 INT3sym（2.810 bpw）的 WikiText2 PPL 损失为 **+12%～+52%**；INT4sym（3.910 bpw）仍有 **+2.4%～+9.5%**。
3. **RoleQ 的边际收益随 bit 增大而衰减**：ternary 时放置规则带来 1.2–2× 改善；INT3/INT4 下，8B/14B 只剩 0.1%–2%，1.7B 是例外（2.8× / 12%）。
4. **0.5% 目标需要 5–6 bit**，或 4-bit + 分组尺度 + SD/QAT + 混合精度；3-bit 纯 PTQ 不可行。

---

## 1. RoleQ 与 bit 宽度正交

重建格式：

```
w ≈ s · (q − z),  q ∈ L 个离散电平
```

| 格式 | 电平数 L | 每码信息位 | resident bpw（含 per-vector scale + norm gains） |
|---|---:|---:|---:|
| ternary | 3 | log2 3 = 1.585 | 1.590 |
| 3-bit 对称 | 7 | log2 7 = 2.807 | 2.812 |
| 4-bit 对称 | 15 | log2 15 = 3.907 | 3.912 |
| 5-bit 对称 | 31 | log2 31 = 4.954 | 4.959 |
| 6-bit 对称 | 63 | log2 63 = 5.977 | 5.982 |
| 8-bit 对称 | 255 | log2 255 = 7.994 | 7.999 |

放置规则不变：

| 角色 | 矩阵 | scale 轴 |
|---|---|---|
| reader | `W_Q, W_K, W_V, W_gate, W_in` | 输出单元（行） |
| writer | `W_O, W_out` | 输入单元（列） |

求解器也只需把“ternary 精确拟合”换成“b-bit 网格精确拟合”：

- writer：每列对补偿后的向量做 **b-bit 网格拟合**，尺度在扫描轴上；
- reader：行网格初始化后固定，扫描结束按  
  `a_i = t_iᵀ H w_i / (t_iᵀ H t_i)` 精修（对任意网格成立）；
- 非对称网格时，精修扩展为 `(s, z)` 的 2×2 最小二乘，仍闭式。

## 2. 论文已有的 3/4-bit 数据

条件：`r1` 随机 Hadamard 基、GPTQ、纯 PTQ、**无 scale distillation**。

|---|---:|---:|---:|---:|---:|
| Qwen3-0.6B | 12.66 | 13.99 | 15.16 | **13.86** | **+9.5%** |

观察：

- 3-bit 最好也只有 +12.2%，离 0.5% 差一个数量级。
- 4-bit 在 14B 上 +2.4%，仍不满足 0.5%。
- 放置规则的收益：INT3 下 8B/14B 仅比 per-OC 好 0.2%–0.3%；INT4 下好 1%–2%。高 bit 时，误差主要由网格、离群值、分组尺度和校准决定，placement 不是主杠杆。

## 3. 0.5% 需要多少 bit

先定义“精度损失”：

| 定义 | 3-bit PTQ | 4-bit PTQ | 4-bit + g128 + SD | 5–6 bit |
|---|---|---|---|---|
| PPL 相对增加 <0.5% | 不可能（+12–52%） | 不太可能（+2.4–9.5%） | 边缘（估 +1–2%） | 可能 |
| Zero-shot/MMLU 绝对下降 <0.5 分 | 不太可能 | 边缘（估 0.5–2 分） | 可能，需混合精度 | 很可能 |
| 相对精度损失 <0.5% | 不可能 | 不太可能 | 边缘 | 可能 |

> 4-bit + SD 与 5–6 bit 的数字是外推估计；论文未对整数网格跑 SD。

### 量级估算

均匀量化 MSE ∝ Δ²/12，每多 1 bit，MSE 降 4×。8B 上：

- ternary：31.28 vs 6.99，误差约 4.5×
- INT3：7.95 vs 6.99，约 1.14×
- INT4：7.20 vs 6.99，约 1.03×

从 3-bit 的 +13.7% 压到 +0.5%，需要约 `13.7/0.5 ≈ 27×` 的误差下降，对应 `log4(27) ≈ 2.4` 个额外 bit，即 **5.2-bit 等效**。因此纯 PTQ 至少需要 5–6 bit。

### SD 的边际收益

SD 在 ternary 8B 上把 `22.42 → 11.33`（约 2×），但这是从极差状态往回拉。3-bit 的额外损失只有 13.7%，SD 最多把超出部分再压一半，乐观估计到 **6%–7%**，仍远离 0.5%。bit 越高，SD 的绝对收益越小。

## 4. 扩展到任意 bit 的实现要点

### 4.1 网格

```python
qmax = 2 ** (bits - 1) - 1
levels = [-qmax, ..., -1, 0, 1, ..., qmax]
w_hat = s * clamp(round(w / s), -qmax, qmax)
```

- 对称网格无 zero point，与 RoleQ 的 scale-only 格式最契合；
- 非对称网格多一个 zero point，bit 记账加 `16/g` 或 `16/d`；
- 4-bit 是硬件友好格式；3-bit packing 与 kernel 支持都更差。

### 4.2 精确网格拟合

三元的前缀扫描是特例。b-bit 对称网格的最优 scale 满足“至少一个权重落在 clipping 边界”，因此候选 scale 可取 `|w|_(i) / qmax`，逐候选计算舍入 MSE 取最小。代价 `O(n²)`（全候选）或 `O(n·C)`（候选子采样）。

### 4.3 求解器

- writer：每列做上述网格拟合；
- reader：初始行网格固定，扫描后闭式精修；
- 分组尺度（g128）可叠加，但会显著削弱 RoleQ 的边际收益。

### 4.4 存储

| 格式 | 信息 bpw | 相对 fp16 的权重大小 |
|---|---:|---:|
| ternary | 1.590 | 10.1× 压缩 |
| 3-bit 对称 | 2.811 | 5.7× |
| 4-bit 对称 | 3.911 | 4.1× |
| 4-bit-g128 | 4.125 | 3.9× |
| 5-bit | 4.958 | 3.2× |
| 6-bit | 5.981 | 2.7× |
| 8-bit | 7.998 | 2.0× |

整机还要保留 fp16 的 embedding + head（Qwen3-8B 约 2.49 GB），因此实际整机压缩低于纯权重压缩。

## 5. 风险与反直觉点

1. **RoleQ 收益随 bit 衰减（论文真实模型实测）**：3-bit 下 8B/14B 仅比 per-OC 好 0.2%–0.3%；加 g128 后可能完全打平。
2. **3-bit 失去无乘法优势**：`{-3..3}` 需要乘法或 LUT；ternary 的 add/sub/skip 优势不再。
3. **敏感层必须单独处理**：embedding/head 已保留 fp16；first/last block、`down_proj`、`o_proj` 通常更敏感，混合精度比统一 3-bit 更可行。
4. **0.5% 接近评测噪声**：论文 8B 单平面 +SD 的 MMLU 是 `47.59 ± 2.72`（两 seed 半极差）；要以 0.5 分为目标，需要更多 seed 和更大评测集。PPL 的 seed 波动小（±0.06），更适合作为 0.5% 的判定指标。

## 6. 推荐路线

| 目标 | 建议 |
|---|---|
| PPL 相对损失 <0.5% | 5–6 bit，或 4-bit-g128 + SD + QAT/蒸馏；不要用 3-bit |
| 任务精度绝对下降 <0.5 分 | 4-bit-g128 + SD + 敏感层 8-bit；先做 bit sweep 验证 |
| 必须 3-bit 且 <0.5% | QAT/PV-Tuning + logit KD + Fisher 混合分配 + 旋转；属于研究级目标，不能从论文结果直接推断可达 |

---

## 7. 最小实验计划

1. 在 `roleq/core.py` 中用 `bits` 参数泛化网格（已完成）。
2. 合成 residual block 上跑 bit sweep（已完成，见 demo part F）。
3. Qwen3-0.6B → 1.7B → 8B：bits ∈ {1, 3, 4, 5, 6}，先 WikiText2，再 7-task/MMLU。
4. 每组至少 2–3 seeds；先用 PPL 筛方案，再确认任务精度。
5. 若 4-bit 仍不达标，叠加 SD、g128、敏感层混合精度。

## 8. 本目录的实现与实测

### 8.1 已实现

`roleq/core.py` 已支持对称 b-bit 网格：

- `bits=1`：ternary，Eq. 2 前缀扫描（全局精确）；
- `bits>=3`：`qmax = 2^(bits-1)-1`，候选 scale 取舍入断点与 `max|w|/qmax`，再做固定码最小二乘精修；
- `bits=2` 会显式报错：2-bit 标准网格是 4 电平非对称（带 zero point），当前实现不支持；
- `quantize_rtn` / `quantize_gptq` / `resident_bpw` 均接受 `bits`；
- reader 精修公式对任意网格不变。

### 8.2 验证

- 27 项单测全部通过（含 3/4/5-bit 网格拟合与 dense scale search 对比、GPTQ ≤ RTN、bit 记账）。
- 3-bit 网格拟合误差与 4000 点 dense scale 搜索的差距 <1%。
- resident bpw：1.590 / 2.812 / 3.912 / 4.959 / 5.982 / 7.999（1/3/4/5/6/8-bit）。

### 8.3 bit sweep（合成单层 residual block，GPTQ）

| bits | bpw | per-OC e2e | per-IC e2e | RoleQ e2e | RoleQ gain |
|---:|---:|---:|---:|---:|---:|
| 1 | 1.590 | 0.5295 | 0.5863 | **0.4729** | 1.12× |
| 3 | 2.812 | 0.3362 | 0.3956 | **0.2816** | 1.19× |
| 4 | 3.911 | 0.1701 | 0.2560 | **0.1175** | 1.45× |
| 5 | 4.959 | 0.0937 | 0.1670 | **0.0614** | 1.53× |
| 6 | 5.982 | 0.0528 | 0.1199 | **0.0347** | 1.52× |

**重要说明**：在这个合成 block 上，RoleQ 的收益并没有随 bit 增大而衰减，反而从 1.12× 升到 1.5×。原因是合成权重被刻意构造成 unit-axis 重尾极强（行/列幅度 `exp(1.2·N(0,1))`），uniform 轴在任何 bit 下都持续吃亏。

论文 Table 3 的 **真实模型** 上，INT3/INT4 的放置收益明显小于 ternary，这是真实权重结构下的经验现象，不是放置规则的数学性质。因此：

- 本 demo 用来验证「RoleQ 在任意 bit 下都不劣于单一 uniform 轴」；
- **不能用它推断真实模型上收益会随 bit 衰减**，那个结论只来自论文的 Qwen3/Llama 实测。
